## Retro

- **Read `RETRO.md` before every branch.** `starting-a-change` does this; carry any trap that applies
  into the plan.
- **When a change hits a correction, a failed check, a review finding, or redone work, draft a
  `RETRO.md` entry in the same PR using the `retro` skill.** Mark it `· Draft`. The human edits and
  approves it at review; only the human removes `· Draft`.
- **Never edit or delete past entries,** and never write an entry when nothing went wrong.
- **Every lesson names what it becomes:** a skill step, a `STANDARDS.md` rule, or a CI check. A
  lesson that never leaves the file will be learned again.
